# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Does not handle timezones (naive datetimes vs IST) or overnight shifts; floor calculation in minutes ignores seconds in grace check. | Overnight shift punch-in after midnight calculates against the wrong date; 09:40:01 IST produces 0 instead of 10. | Converted instants to IST, anchored shifts to attendance date (accounting for overnight shifts), and enforced strict 600s grace check per R2. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies banker's rounding (round-half-to-even) instead of deterministic half-up rounding. | A duration resulting in `2.345` hours rounds to `2.34` instead of `2.35`. | Used `Decimal.quantize()` with `ROUND_HALF_UP` per Rule R4. |
| 3 | `compute_overtime` (lines 44-47) | Missing 30-minute minimum threshold (R3); sets `end` on `date_str` without shifting next-day end for overnight shifts. | 1 minute past shift end awards 1 minute overtime; overnight shift awards negative or 18+ hours overtime. | Added `>= 30` minute check (returns 0 otherwise), and anchored overnight `shift_end` to `att_date + 1 day`. |
| 4 | `health` (lines 72-74) | Returns `{"status": "ok"}` statically without verifying MongoDB connection. | Returns HTTP 200 even when MongoDB is down or unreachable. | Ping MongoDB using `client.admin.command("ping")`; return HTTP 503 if unreachable. |
| 5 | `create_employee` (lines 78-85) | Check-then-insert race condition; missing validation for `shift_start != shift_end`; sets `created_at` using local naive datetime. | Concurrent requests with same `emp_code` create duplicates; equal shift times return 201 instead of 422; `created_at` returned as string/ISO rather than epoch ms. | Created unique index on `emp_code`, caught `DuplicateKeyError` to return 409, added Pydantic validator, and stored UTC BSON date returning integer epoch ms. |
| 6 | `list_employees` (lines 88-96) | Off-by-one pagination bug (`skip = page * page_size`); `total` counts whole collection instead of filtered set `q`; missing sort by `emp_code` ascending. | Querying `page=1` skips the first 20 records; filtering by department still returns total count of all departments. | Changed skip to `(page - 1) * page_size`, counted `db.employees.count_documents(q)`, added `.sort("emp_code", 1)`, and added Query validation. |
| 7 | `punch_in` (lines 99-106) | Check-then-insert race condition on `attendance_logs`; missing 404 check when employee does not exist; accepts invalid status strings. | Concurrent punch-ins create duplicate records for same date; nonexistent `emp_code` crashes with 500 `TypeError` on `emp["shift_start"]`. | Added unique compound index on `(emp_code, date)`, caught `DuplicateKeyError` returning 409, checked employee existence (404), and validated status. |
| 8 | `punch_in` (lines 102-103) | Timestamp parsing does not validate epoch millisecond bounds; assigns date using local time instead of IST calendar date (R1). | Passing seconds (`1712345678`) succeeds instead of 422; overnight punch-ins at 05:00 IST get assigned to current date instead of previous day. | Validated epoch ms range (`>= 100000000000`), truncated to whole seconds, and resolved attendance date in IST using overnight shift logic. |
| 9 | `punch_in` (lines 118-121) | Exposes internal MongoDB `_id` as `doc["id"] = str(res.inserted_id)`; returns datetime object instead of epoch ms. | Response contains forbidden `"id"` field; serialization fails or returns ISO strings instead of integer ms. | Removed `_id` and `"id"` from output; converted datetimes to epoch milliseconds. |
| 10 | `list_attendance` (lines 144-150) | In-memory sorting and pagination (`list(db.attendance_logs.find(q))` followed by `docs.sort()`); exposes internal `"id"`. | Server runs out of memory or times out on 100,000 records; response contains forbidden `"id"` field. | Replaced in-memory sorting with MongoDB indexed query `.sort([("date", -1), ("emp_code", 1)]).skip().limit()`, formatted epoch ms, and removed `"id"`. |
| 11 | `list_attendance` (lines 125-132) | Missing date range validation when `date_from > date_to`. | Sending `date_from=2026-07-10&date_to=2026-07-01` returns empty 200 instead of 422. | Added validation raising HTTP 422 when `date_from > date_to`. |
| 12 | Whole file (missing endpoints & indexes) | No index creation at startup; completely omitted 6 endpoints (`punch-out`, `regularize`, 4 analytics aggregations, and `explain`). | All queries perform COLLSCAN; missing endpoints return 404. | Implemented FastAPI lifespan hook creating indexes idempotently, and implemented all remaining contract endpoints and aggregation pipelines. |

## Not a Defect
- **Reading `MONGO_URI` and `MONGO_DB` with fallback to `localhost:27017` / `attendance_db`**: This adheres to the environment contract where real environment variables take priority over local `.env`, enabling seamless grading. We preserved this behavior and added `tz_aware=True` to MongoClient to ensure consistent UTC datetime handling.
